工作原理

Mac 完全不变，由安卓设备负责监听。

由安卓设备负责监听，Mac 负责连接 — 这正是它能在 WiFi 下零配置运行的原因， 通过 mDNS 自动发现，无需对原版 OpenDisplay Mac 应用做任何改动。

MAC （服务端，原版 OpenDisplay 应用）

  1. CGVirtualDisplay
  2. → ScreenCaptureKit → VideoToolbox H.264
  3. → TCP [4-byte length][Annex-B frame] ═══→
  4. ← control JSON (hello, touch, scroll, ping) ═══

ANDROID （本项目）

  1. listens on :9000
  2. → MediaCodec → SurfaceView

功能

目前已经能用的功能。

针对真实的 Mac 应用验证过，不是纸面规格。

硬件 H.264 解码

MediaCodec 直接解码到 Surface，无需 CPU 转换。

自动发现

通过 mDNS（_opensidecar._tcp）— Mac 会在同一网络中自动找到安卓设备。

触摸与滚动

在 Extend 模式下，单指变成点击/拖拽，双指变成滚动。Mac 的 Mirror 模式仅供查看：会静默忽略任何客户端的输入。

双指缩放

在视频上双指张开即可本地缩放，Mirror 和 Extend 模式都可以 — 无需改动协议，触摸依旧精准落在 Mac 上的对应位置。缩放后，用三指拖动可以在放大区域内移动。

远程光标

一个圆点或解码出的光标图案，实时映射 Mac 的光标位置。

前台服务

应用切到后台也能存活，解锁屏幕后能正确恢复。

错误恢复

解码器出错会自动请求关键帧，而不会断开连接。

手动兜底

可编辑的 mDNS 名称和 IP:端口连接方式，供自动发现失败时使用。

USB 配件（AOA）

插上数据线，点一下系统弹窗，就这么简单 — 不需要 adb，不需要开发者选项。

画中画

连接状态下离开应用，视频会继续在悬浮窗口中播放。

无账号，无遥测

和原项目理念一致：没有中心服务器，不会往外发送任何数据。

常见问题

常见问题解答。

这和 iOS 版 OpenDisplay 是同一个应用吗？

不是。这是一个独立客户端，用 Kotlin 从零编写，实现了相同的网络协议以便和原版 Mac 应用互通。官方项目只提供 iOS/iPadOS 客户端。

有上架 Google Play 吗？

Google Play 版本目前处于封闭测试阶段。想成为测试者吗？发邮件到 josepacelli@gmail.com。与此同时，也可以通过 GitHub Releases 获取 — 用 adb install 安装，或把 APK 复制到设备上安装 （需开启"未知来源"）。

必须要 WiFi 吗？

通过 WiFi 使用 mDNS 自动发现即可运行。也可以用 USB 作为原生配件（AOA）连接 — 插上数据线，点一下系统弹窗即可，无需 adb。仓库中有针对尚不支持 AOA 的 Mac 应用的 回退方案说明。

Mirror 模式下触摸能用吗？

不能 — Mac 上的 Mirror 模式仅供查看。Mac 应用只在 Extend 模式下接受触摸/滚动（镜像会话根本不会 创建输入注入器），所以从这里发出的点击和滚动都会被静默忽略。需要交互操作请使用 Extend 模式。

所有安卓平板或手机都能用吗？

需要安卓 8.0（API 26）或更高版本。已在真实设备上测试（三星 Galaxy Tab S9 FE+ 和 Galaxy Note10+/Tab S7+，安卓 12 至 16），但尚未覆盖广泛的机型 — 触摸/滚动/光标功能已实现， 但目前的实际验证还比较有限。注意：v0.0.7 及更早版本在安卓 12–13（API 30-33）上启动会崩溃； 请使用 v0.0.8 或更新版本（已在 #5 中修复）。

会改动 Mac 应用吗？

完全不做任何修改 — 任何协议不兼容都是本项目的责任，与上游项目无关。

许可证是什么？

GPL-3.0，与原项目相同。开源，可自由使用，包括商用；分发的修改版必须以同一 许可证继续开源。
